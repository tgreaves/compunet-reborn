# 3D printing — the Compunet logo

A printable version of the Compunet logo, for multi-colour FDM printers (built against the Bambu
workflow).

| File | What it is |
|---|---|
| `compunet-logo-prepared.3mf` | **The print-ready project** — plated, coloured and sliced in Bambu Studio; the version published to MakerWorld. Start here if you just want to print it |
| `compunet-logo.3mf` | The **generated** file: both variants as two models on the plate, no printer settings — see below |
| `parts/*.stl` | The flush variant's parts separately — the fallback route, see below |
| `compunet-logo.stl` | Everything merged, single colour — preview, or a one-colour print |
| `logo3d.py` | The generator. Re-run it to change size, thickness or style |

**⚠ `compunet-logo-prepared.3mf` is hand-edited and is NOT regenerated by `logo3d.py`.** Running
the generator overwrites `compunet-logo.3mf` only; the prepared project keeps the plating and
print settings that were set up by hand in Bambu Studio, and re-running the generator will not
touch it. If the geometry changes, the prepared file has to be redone in the slicer — which is
the reason it is tracked separately rather than treated as build output.

What it carries beyond the generated file:

| | |
|---|---|
| Filaments | `#0000DD` blue, `#CCCCCC` grey, `#DD0000` red — the §A.3 palette values |
| Printer | Bambu Lab H2C, 0.4 nozzle, 0.2 mm layers, 15% sparse infill, supports off |
| Plate | Both variants laid out (212.5 × 42.5 mm flush, 212 × 42 mm raised) plus the wipe tower |
| Extras | Plate thumbnails, which MakerWorld uses for the listing preview |

## There is no source image

The logo does not exist in this repository as artwork. It is a **PETSCII frame** —
`server/data/content/root/header.seq`, the Part-1 header the server sends at the top of the root
directory. `logo3d.py` renders that frame the way a client would (glyphs from the specification's
appendix font, colours from its appendix palette, §5/§6) and extrudes the resulting pixels.

So the print is generated *from the spec*, not traced from a picture. Change the header frame or
the font and the model follows.

## Two variants — pick one, delete the other

The 3MF contains **two models side by side**. Open it, delete the one you do not want, slice the
other:

| Variant | Top face | Height |
|---|---|---|
| **flush** | one continuous plane — the colours are **inlaid** 0.8 mm into the top | 15.0 mm |
| **raised** | the lettering and rules stand **2.5 mm proud** of the plate | 17.5 mm |

The two depths differ on purpose: an inlay reads because it is a *colour*, so 0.8 mm is plenty,
while relief reads by **shadow** — at this size 0.8 mm casts almost none, and the lettering
disappears at a glance. Adjust with `--inlay` and `--relief`.

They are separate objects with separate build items, 12 mm apart, so deleting one leaves the
other untouched.

## Printing it

| Part | Extruder | Colour | C64 palette |
|---|---|---|---|
| `plate` | 1 | light grey `#CCCCCC` | 15 — the slab |
| `plate-top` | 1 | light grey `#CCCCCC` | 15 — flush variant only: the top layer, with the artwork cut out of it |
| `ink-2` | 2 | red `#DD0000` | 2 — the lettering |
| `ink-6` | 3 | blue `#0000DD` | 6 — the rules above and below |

**Three filaments** — the two grey parts share extruder 1. Load matching filaments in those AMS
slots, or remap in the slicer (right-click a part → change filament). The RGB values are the
authentic C64 ones from the specification's §A.3 table.

**Dimensions as shipped:** 200 × 30 mm of artwork on a 212 × 42 mm plate, **15 mm thick** — a
solid block that stands on its long edge. Both variants together occupy 212 × 96 mm. Thinnest
feature is 2.5 mm, comfortably above a 0.4 mm nozzle.

**Drop the infill.** At 15 mm this is mostly empty volume; nothing structural happens below the
top 0.8 mm, so 10 % is plenty.

**No supports, no brim** — a flat slab. Print face-up.

**One colour change only.** On the flush variant everything below 14.2 mm is plain grey, and the
grey top layer, red lettering and blue rules share the final 0.8 mm — at 0.2 mm layers that is 71
plain layers then 4 multi-colour ones, so the AMS purges over four layers rather than throughout
the print. The raised variant is the same idea with the colour above 15 mm instead of inside it,
over 12 layers.

If the slicer offers to repair the mesh, let it. Adjacent rectangles share coincident faces,
which is technically non-manifold; every slicer unions it correctly and the shape does not
change.

### If Bambu Studio ignores the colours

It may. On import it warns *"The 3mf is not from Bambu Lab, load geometry data and color data
only"* — it discards part/extruder assignments from any 3MF it did not write itself. Colour is
carried three separate ways in this file (below) in the hope one survives, but the guaranteed
route is to assemble the parts by hand, which takes about thirty seconds:

1. Open `parts/compunet-logo-plate.stl` as the object.
2. Right-click it → **Add part** → `parts/compunet-logo-plate-top.stl`.
3. Right-click → **Add part** → `parts/compunet-logo-ink-2.stl` (the red lettering).
4. Right-click → **Add part** → `parts/compunet-logo-ink-6.stl` (the blue rules).
5. Assign a filament to each part.

All parts share one coordinate origin, so they land aligned — do **not** re-centre them
individually. (`parts/` holds the **flush** variant; for raised, run
`logo3d.py --only raised` first.)

> **⚠ If you are editing this generator:** colour lives in a Materials-extension
> `<m:colorgroup>` with a per-triangle `pid`/`p1`, *not* in `<basematerials>`. The core
> `basematerials` element looks like the obvious choice and is silently ignored by
> PrusaSlicer-lineage slicers, which then load the model in a single colour — that was the first
> attempt here, and it looked correct in every structural check. The sidecar volume configs
> (`Metadata/Slic3r_PE_model.config` for PrusaSlicer, `Metadata/model_settings.config` for
> Bambu/Orca) divide each mesh into parts by **triangle range**, and are what those slicers use
> for filament assignment — when they trust the file.
>
> ⚠ Extruders are assigned per **colour**, not per part. The flush variant has two grey parts,
> and numbering them separately asks for a four-filament print of a three-colour model.

## The website copy

All three downloads are served from the site's Extras page, as copies in `website/static/`.
**They are copies, not links** — after regenerating here, re-copy them or the download will drift
from the generator:

```bash
cp 3dprint/compunet-logo-prepared.3mf 3dprint/compunet-logo.3mf 3dprint/compunet-logo.stl website/static/
```

The Extras page recommends `compunet-logo-prepared.3mf` and offers the other two as the
plain-model and single-colour alternatives.

## Regenerating

```bash
python 3dprint/logo3d.py                        # both variants, 200 mm wide, 15 mm thick
python 3dprint/logo3d.py --thickness 6          # thinner — a plaque rather than a block
python 3dprint/logo3d.py --width 120            # smaller
python 3dprint/logo3d.py --only flush           # one variant instead of both
python 3dprint/logo3d.py --only bare            # colours only, no plate (magnet, inlay, glue-on)
python 3dprint/logo3d.py --gap 20               # spacing between the two variants
python 3dprint/logo3d.py --relief 4             # taller raised lettering
python 3dprint/logo3d.py --inlay 1.2            # deeper inlay on the flush variant
python 3dprint/logo3d.py --seq server/data/content/courier-header.seq --rows 8
python 3dprint/logo3d.py --out /some/where      # write elsewhere
```

Default inlay depth, relief height, margin and backing colour are constants at the top of
`logo3d.py`.

Needs nothing installed: the standard library plus this repository (it imports the server's
frame renderer and reads `client/web/assets.json` for the font and palette).

## How it works, briefly

1. Render the header frame to a 40×24 cell grid (`api_binding.frame_to_cells`).
2. Expand each cell to its 8×8 glyph bitmap → a 320×48 pixel map with a colour per pixel.
3. **Merge pixels into rectangles**, greedily. Without this the logo is ~7,000 pixels → 84,000
   triangles of mostly co-planar faces. Merged it is ~150 rectangles and ~1,800 triangles.
4. Extrude each rectangle into a box; group boxes by colour into one mesh per colour.
   - *flush*: the plate also gets a top layer built from the artwork's **negative** — every pixel
     that is not ink — so the colours drop into the holes it leaves. The two exactly tile the
     plate area, which the generator checks.
5. Concatenate each variant's parts into **one** mesh per variant, recording each part's triangle
   range, and write those ranges as volumes with an extruder number. One object per variant, so
   the two are separately selectable; parts within a variant are one object, so a slicer treats
   them as parts rather than as overlapping models.
